# 与 Windows 版（Tauri）差异审计

对象：A 版 = `src-tauri/` + `src/`（Windows 交付的 Tauri 2 + Vue 3）；
B 版 = `macos/Sources/`（本机原生 SwiftUI 版）。
方法：两轮独立静态审计（领域规则与持久化 / 界面与交互），逐条对照并标注 `file:line`；
下表结论除注明「已实测」外均为静态分析，尚未逐条实机验证。

## 一、本次已修复的 B 版缺陷

| 缺陷 | 现象 | 位置 |
| --- | --- | --- |
| 作业卡 `⌃↩` 完全失效 | `fieldOrder` 存的是行 id（`语文#0`），`toggleCurrentField` 却拿它当学科名比对 `subject`，永不命中；作业条目的「明天交」标记无法用键盘切换 | `AppState.swift:536`（原） |
| 放映中仍可换天 | 全屏放映时 `handleKey` 只是放行按键（`return false`），菜单快捷键 `⌘T` `⌘[` `⌘]` 照旧生效，投影内容会当场跳天 | `AppState.swift:385`、`HomeworkMacApp.swift:51-56` |
| 结构性字段被静默降级（H3） | 缺失 / 显式 null / 类型不符一律回退默认值：`days` 被写成 `null` 时得到 `days = [:]` 且 `Store.load` 仍算成功，不走备份恢复、不提示，看起来就是「所有天都没了」 | `Model.swift:29-31`（原） |
| 修 H3 时发现的连带缺陷 | 用来区分「字段缺失」的 `keyNotFound` 捕获会把**嵌套元素**抛出的同类错误一起吞掉——`homework` 里某个条目缺字段会被静默丢成空数组 | `Model.swift` 的 `decodeDefaulted` |

修复：`toggleCurrentField` 按 `学科#序号` 解析后映射到真实下标；`goToday`/`stepDay` 增加 `isPresenting` 守卫，
菜单项同步 `.disabled`；解码改为「缺失→默认值、显式 null/类型不符→整体失败」，
并用 `container.contains` 而非捕获 `keyNotFound` 来区分两种情形。

验证：`swift test` 40 个用例（新增 10 个：fixture 解码 / 结构字段 null 拒绝 / 类型不符拒绝 /
条目缺字段拒绝 / 可选字段接受 null / 旧字段忽略 / 恢复链路）、`cargo test` 27 个用例通过；
并用真实数据文件（仓库内 Windows 版数据与 `~/Documents/每日作业数据`）实跑严格解码，两者均正常加载。

## 二、高危差异（需决策，未改动）

### H1 自动出图：内容、文件名不同 —— **已按新语义修复**

原先 B 版自动出图跟着当前视图走（`viewDate` + `submitOnly`），并沿用 `displayDate` 命名，
停在别的日期时会「删掉今天的图、写成那天的图」。现在两端语义统一为：

| | 自动出图 | 手动出图（⌘D / Ctrl+D / 工具栏 / 放映右键） |
| --- | --- | --- |
| 内容 | 今天 + 全部（固定） | 当前屏幕所见（页面日 + 当前模式，含「仅要交」过滤） |
| 文件名 | `家庭作业_<今天>.png` | `家庭作业_<页面日>.png`——用**你选中那一天**，不用画面日期 |
| 清理 | 删除其他日期的家庭作业图片，只留一份 | 同左 |

修复点：B 版 `tickAutoImage` 改走 `forToday: true`，命名改用 `vm.date`（页面日）；
A 版 `image.ts` 手动出图改取当前视图并把页面日传给后端，`export_image` 新增 `date` 参数、
落盘逻辑抽成可测的 `store::write_image`（含日期校验与只留一份）。

仍保留的平台差异（有意为之，不影响使用）：**落盘目录**——A 版写 exe 同级，B 版写数据目录
（macOS 上 `.app` 包内不可写，写进去还会破坏代码签名）；**导出尺寸**——A 版 1920×1080，
B 版 3840×2160（发群看图更清晰，二者都是同一画面，仅像素密度不同）。

### H2 节假日/调休：B 版让系统日历压过用户数据

- B 版 `isSchoolDay` 先问 EventKit：日历判为假日 → 即便 `data.days[date]` 有用户建的天也返回 false；
  判为工作日 → 即便软件里没建这天也返回 true（`Schedule.swift:166-173`）。A 版只有「`days` 里有条目」一个来源（`schedule.rs:139`）。
- 触发：假期中给某天建过作业天，A 版当上学日、B 版跳过；周五遇日历调休周六而周六模版为空时，
  B 版的演讲建议会整体变空。
- 自相矛盾：`adoptMakeupDay` 用 `addDay(date, copiedFrom: nil)`（`AppState.swift:160-169`），
  生成的调休日取周六/周日模版（全空），「一键加入调休日」得到的是一张空课表。
- 另有一致性问题：B 版对法定节假日把课表整体置空（`Schedule.swift:246`），但作业建议仍按未置空的课表算（`:251`），
  周总览也不置空（`:257-266`）——自己「建议有课、画面无课」。

建议：`isSchoolDay` 让「用户建过天」优先于日历假日；`adoptMakeupDay` 明确课表来源（默认取上一个工作日的星期几）。

### H4 放映版式改形：作业卡会拆列，字号可超过公告

| 项 | A 版 `layout.ts` | B 版 `Slide.swift` |
| --- | --- | --- |
| 多条作业 | 行内流水（序号 + 空格，可同排）`:302-320` | 每条独占一行，装不下就整卡拆左右两列 `:343-362,426-445` |
| 字号 | 公告 52 最大、作业 28~46、课表 40、演讲 36 `:115-117,159,198` | 公告 44、作业 22~**56**、课表 33（不收缩）、演讲 34（不收缩、无截断）`:172,345,594,636,673` |
| 外边距/头部 | margin 28、gap 20、头 112 `:4-5,75-87` | margin 36、gap 22、头 132 `Theme.swift:7-12`、`Slide.swift:127` |

后果：作业 6 条以上时两版观感明显不同；B 版作业字号可大于公告，题目多时可能顶出卡片。

### H5 放映中的反馈看不见

A 版 toast 压在黑幕上可见（`App.vue:193`、`style.css:148-160`）；B 版 toast 只挂主窗口
（`MainWindow.swift:46,182-203`），全屏放映时右键「切换为仅要交」没有任何可见反馈。
建议把 toast 也叠加到 `PresentWindow`。
